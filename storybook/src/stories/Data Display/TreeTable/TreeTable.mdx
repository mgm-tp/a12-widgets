> ℹ️ `TreeTable` remains fully supported. Its experimental counterpart, **Data Display › DataTreeTable**,
> is a hierarchical wrapper over `DataTable` that works on your own row type instead of a
> `TreeNodeModel` envelope, needs no `DndProvider`, and adds keyboard drag-and-drop, lazy loading and
> pagination. A mapping between the two APIs is in the showcase's migration notes.

The `TreeTable` widget displays hierarchical data in a multi-column table — think file explorers,
organization charts or nested categories. It takes a single `root` node (each node has an `id`,
`data` for its cells, an optional `icon` and optional `children`) and a list of `columns`, where
one column is marked `hierarchical` to host the expand/collapse arrows.

- Expansion state is controlled by the consumer: toggle `collapsed` via `rowStyling` in response to
  `onArrowClick` from `rowEventHandlers`.
- `rowStyling` also drives `selected`, `disabled`, `highlighted` and `interactive` row states.
- Use `hideRoot` to show the root's children as top-level rows, and `scrollToNode` to scroll to a
  row programmatically.
- `dragDropOptions` enables drag-and-drop reordering and re-parenting of nodes. It is built on
  react-dnd, so the table has to be wrapped in a `DndProvider` (see the drag-and-drop examples).

## Drag and drop

Wrap the table in a `DndProvider` (backend `DragAndDropUtils.DefaultDndBackend`) and pass
`dragDropOptions`. A drop target is a combination of a row and a `TreeTableNodeDropPosition`:

| Position   | Meaning                                                    |
| ---------- | ---------------------------------------------------------- |
| `TOP`      | Insert above the hovered row, as its sibling                |
| `BOTTOM`   | Insert below the hovered row, as its sibling                |
| `AS_CHILD` | Append into the hovered row (hovering the middle of a row)  |

The table never mutates the tree itself — `onDrop` reports `{ dragItem, dropResult }` and the
consumer applies the move to its own `root`.
