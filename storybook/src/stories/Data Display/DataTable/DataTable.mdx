# DataTable

> ⚠️ **Experimental.** `DataTable` is the CSS-grid-based successor to the production `Table`,
> shipped from the `/experimental` entry point. The API may still change. Consumer documentation
> and migration notes live in the showcase; these stories are the isolated reproductions used for
> development and QA.

`DataTable` renders a native `<table>` driven by CSS: column tracks are CSS custom properties on
the table root and pinned columns use `position: sticky`, so there is no imperative column-width
sync and no per-row scroll containers. That makes it lighter than the production `Table` while
keeping native table semantics for accessibility.

```tsx
import { DataTable } from "@com.mgmtp.a12.widgets/widgets-core/experimental";

<DataTable
	ariaLabel="Employees"
	data={rows}
	columns={[
		{ label: "ID", dataKey: "id", width: 0.7, fixedWidth: true },
		{ label: "Name", dataKey: "name", sortable: true },
		{ label: "Department", dataKey: "department" }
	]}
	rowKey="id"
/>;
```

**New here?** Open **DataTable › Playground** to toggle the display props live, or
**DataTable › Full Example** for a realistic assembly (sorting + pinning + filter row +
selection + footer).

### Customizing presentation — three layers

Pick the narrowest tool that fits:

1. **Column render hooks** (`renderCell` / `renderHeader` / `renderFooter` / `renderFilter`)
   own the presentation of **one column** while `dataKey`/`dataGetter` still resolves the
   value, so sorting, footers and filtering keep working. → _Customization › Render Hooks_
2. **Content slots** (`headContent`, `cellContent`) transform **every** column's label or
   value from one place, falling back to `defaultContent`. → _Customization › Slots_
3. **Structural slots** (`row`, `cell`, `contextMenu`, …) take full control of an element.
   Slot components need **stable identity** (module scope or memoized) and should compose the
   self-wiring `DataTable.*` primitives so sorting/selection/keyboard/context-menu stay intact.
   → _Customization › Slots_

## Feature compatibility

| Feature                 | Requires    | Notes                                                                                                                                                             |
| ----------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `virtualScrollOptions`  | `maxHeight` | Row groups are **silently disabled**. `rowExpansion` renders only with dynamic row heights (omit `rowHeight`). Drag-and-drop and column resize work.              |
| `infiniteScrollOptions` | `maxHeight` | **Overrides** `virtualScrollOptions` when both are set. Same constraints as virtualization.                                                                       |
| `cellHighlighting`      | a header    | Forced **off** in `cardView`, when `disabled`, or when `hideHeader` is set.                                                                                      |
| `cardView`              | —           | A separate card layout with no `<table>` DOM. Renders **no header and no footer**; ignores `gridRole`, `rowHeight`, pinning and column resize.                    |
| `disabled`              | —           | Suppresses all event handlers; `rowStyling`, `cellStyling` and `cellHighlighting` go inactive.                                                                    |
| `actionColumn` width    | —           | A width-less action column **auto-sizes** to its buttons and header (`actionColumnAutoSize`, default on). An explicit `width`/`fixedWidth` always wins; opting out yields a fixed `150px` track. |
| `pinning`               | —           | Allowed on top-level columns only; sub-columns inherit their group's side.                                                                                        |
