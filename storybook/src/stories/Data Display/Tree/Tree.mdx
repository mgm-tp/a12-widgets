> ⚠️ **Deprecated since 39.0.0.** The `Tree` template and its behavior HOCs (`TreeAdapter`,
> `Collapsible`, `Selectable`, `DragDrop`, `Insertable`) keep working but will be removed in a future
> release. New trees should use **Data Display › TreeView**, a single headless-model-driven component
> from the `/experimental` entry point; the migration notes live in the showcase under
> _Get Started › Migration Instructions › New Table and Tree Components_. The low-level `TreeContainer`
> / `TreeNode` primitives are not deprecated.

The `Tree` widget renders hierarchical data such as file systems or navigation structures. It is
composed via a behavior chain: `TreeAdapter` adapts the plain template to a model-driven API and
must come first, while `Collapsible` and `Selectable` add expand/collapse and selection behavior
on top (e.g. `Selectable(Collapsible(TreeAdapter(Tree)))`).

- Nodes are described by `TreeNodeModel` objects (`id`, `label`, `icon`, `children`, `disabled`, `highlightVariant`).
- `tplTreeNode` maps every node to its template, e.g. to attach `actionButtons` or custom content.
- `hideRoot` hides the top-level node; `scrollToNode` provides programmatic scrolling to a node by id.

## Keyboard navigation

The tree supports full keyboard navigation: **↑ / ↓** move between nodes, **→** expands a node or
moves to its first child, **←** collapses a node or moves to its parent, and **Enter** / **Space**
select the focused node. The `KeyboardNavigation` sidebar entry additionally covers the
`arrow-only` mode (configured via `KeyboardNavigationConfigProvider`) and navigation across node
action buttons.
